# AGENTS.md

Personal website of Benedikt Ritter ([britter.dev](https://britter.dev)): Astro 7 static site, npm, Tailwind CSS v4, deployed to Netlify. Dependency updates are handled by Renovate — don't open version-bump PRs manually.

## Environment

- Dev environment comes from the Nix flake via direnv (`.envrc`: `use flake`). It provides Node and the pre-commit hook.
- Node versions differ on purpose-ish: dev shell and Netlify use Node 24, CI and `engines` in `package.json` use 26.x. npm only warns on mismatch.
- `.pre-commit-config.yaml` is generated by git-hooks.nix (`DO NOT MODIFY`). To change hooks, edit `flake.nix` and run `nix flake check` / re-enter the shell.

## Commands

- Dev server: `npm run dev` → http://localhost:4321
- Build (includes typecheck): `npm run build` (= `astro check && astro build`) — there is no separate typecheck script
- Format check: `npx prettier . --check` (CI runs this; pre-commit formats staged files)
- Functional tests: `npx playwright test --project=functional` (no browser needed — all tests use the `request` fixture)
- Visual regression: only via `./run-visual-tests.sh` (Docker) — same as CI. Don't use `npm run test:visual` or `npx playwright install`: browser downloads don't work on NixOS hosts
- Update visual snapshots: `./run-visual-tests.sh --update-snapshots` (the script forwards extra args to `npx playwright test`)

Playwright auto-starts the dev server on port 4321 (`webServer` in `playwright.config.ts`) and reuses an already-running one outside CI.

## Testing quirks

- Visual regression runs only in Firefox with light color scheme; snapshots are committed in `tests/visual-regression.spec.ts-snapshots/`. If you intentionally change UI, update snapshots in the same PR with `./run-visual-tests.sh --update-snapshots` and commit the changed PNGs.
- The Docker image tag in `run-visual-tests.sh` must match the pinned `@playwright/test` version.
- Functional tests hit the dev server and assert meta tags, titles, RSS feed, and redirects — redirect changes in `astro.config.mjs` are covered there.

## Content and structure

- Blog posts live in `src/content/blog/` as `YYYY-MM-DD-slug.md` (or `.mdx`). The publish date and the URL `/blog/YYYY/MM/DD/slug` are derived from the filename; the build throws if the date prefix is missing. Frontmatter: `title`, `description`, `topics` (array), `updated` (optional date). No separate date field.
- OG images (satori + resvg) are generated at build time in `src/pages/og/`; each blog post gets `/og/<id>.png` automatically. Don't hand-create OG images.
- Redirects for old paths are in `astro.config.mjs` (`redirects`); the domain 301 from benediktritter.de is in `public/_redirects`.
